## Conclusion: **mixed — predominantly genuine model behavior, small prompt-noise component**

Three independent signals:

1. **Aggregate degeneracy rate is essentially flat.** 35% → 40% (strict heuristic) or 30% loops-only. Within run-to-run noise for n=20 non-deterministic. Fixing the wrong-code descriptions did NOT reduce the rate.

2. **WHICH scenarios degenerate shifted substantially.** PR #8's three documented catastrophes (Camry P0420 273× "SERVICE NOTES:" loop, Civic P0171 30+× "[Image Placeholder]", BMW M5 P0455 dropping the code) → in this rerun:
   - **Camry P0420 is now clean** (fmt 6/12, 3730 chars, no loop) ← the canonical-description fix did help this case
   - **Civic P0171 still loops** but with a different phrase ("Disclaimer:" 60×)
   - **BMW M5 P0455 is now clean** (fmt 2/12 is low but no loop)
   - NEW loops appeared at Civic P0300, Civic P0011, BMW P0420, BMW P0171, Camry P0171 — none of which were degenerate in PR #8 specifically

   So the wrong-code descriptions were causing ~3 specific degeneracies; the model produced ~3 new ones in their place. Net zero.

3. **Latency dropped 27%** (44.25s → 32.45s mean) — uniformly, including across non-degen scenarios. Attributable to:
   - `OLLAMA_KEEP_ALIVE=24h` (PR #11's A4500 work, commit `098bc49`) eliminating cold-start tax (~3s × ~20 calls would be measurable)
   - Canonical lookup bypassing CarsXE round-trips for OBD-code description (~0.2–0.5s/call when not cached, but most CarsXE calls were cached from PR #8 — partial)
   - Possibly: the canonical descriptions being shorter / cleaner produces slightly shorter outputs overall

The latency win is the only clearly attributable improvement. Format and degeneracy are unmoved at the aggregate. **Fine-tuning is still load-bearing**, possibly slightly *more* so than PR #8 suggested — the model loops on long structured outputs regardless of prompt cleanliness.

## Known issues with this rerun (NOT FIXED — observation only per the brief's hard prohibitions)

1. **`scripts/baseline_score_responses.py` has a hardcoded date** at line 25: `REPORT = ... "baseline-gemma-format-validation-2026-05-18.md"`. When run, the scorer reads PR #8's data, writes vs-scores back to PR #8's file, and prints aggregates from PR #8 — not from the rerun. Its terminal output ("fmt=3.5/12, vs=2.4/5, degen=7/20, latency=44s mean") is the PR #8 cached aggregate, not the rerun's. The file modification was reverted (`git checkout --`); the bug remains. Vehicle-specificity scores for this rerun are NOT computed.
2. **Latency outlier:** Silverado P0420 took 80.9s for a non-degenerate 2/12 response. May indicate a cold-start cost on the very first call (KEEP_ALIVE re-armed during the rerun but the model may have been evicted between sessions). The next 19 calls averaged 30.0s.
3. **Heuristic degeneracy detection** in this report differs from PR #8's manual classification. The PR #8 scorer's `ki=degenerate` annotation came from a different (also hardcoded) path. The 35% baseline is taken at face value for comparison.

## What this means for the WESEF plan

- The CarsXE wrong-decode fix was net-zero on degeneracy — useful for accuracy of grounding, useless for output stability.
- The fine-tune target should explicitly address loop-prevention. `repeat_penalty=1.1` in `ollama_client.py` is still untried and is the cheapest sampling-level fix on the deferred list from `notes/2026-05-18-a4500-optimization.md`.
- Per-scenario shifts (good cases turning bad, bad cases turning good) suggest non-deterministic generation is dominating; pinning a seed would make rerun signals stronger but Ollama's seed plumbing is non-trivial.
- Bottom line for the PR #8 → rerun comparison in the WESEF eval section: **"the prompt-pipeline fix produced an unambiguous latency improvement (−27%) and resolved 2 of 3 documented catastrophic-failure cases, but the aggregate degeneracy rate was statistically unchanged. The remaining failure modes are not attributable to upstream data quality."**

### Updated bottom line

- Vehicle-specificity: 2.4 → 2.8 (+17%). Modest improvement, likely from cleaner code descriptions letting the model name the right system instead of the wrong one.
- Latency: −27% (44s → 32s). Largest unambiguous win, attributable to `OLLAMA_KEEP_ALIVE=24h` + canonical lookup bypassing CarsXE round-trips.
- Format adherence: 3.5/12 — completely unmoved. **Fine-tuning is still load-bearing on format**, identical conclusion to PR #8.
