# Brief 2c: Training data distillation

Executor: Claude Code, ClearDrive repo root. Runs after Brief 2a's freeze commit exists (tag `eval-v1-frozen`). If the tag does not exist, STOP at step 0.
Architect: Claude Opus. Do not redesign. If a step cannot be done as written, log it in the report and stop.

## Purpose

Turn the ~15k raw scraped records into 3 to 5k curated training pairs for QLoRA. Pairs are generated by Claude Opus via OpenRouter (the designated synthesis model under the integrity firewall). Nothing in the frozen eval set may leak into training.

## Hard prohibitions

1. Do NOT read, copy, or reference anything under eval/ except eval/eval_set.json, eval/codeless_set.json and eval/taxonomy.json, and only for exclusion and label lookup (steps 2 and 3).
2. Do NOT use any eval-condition model (the pinned Qwen base, Gemma, Llama, the fine-tuned model) to generate or filter training pairs. Synthesis model is Opus via OpenRouter only.
3. Do NOT start training. This brief ends with a validated JSONL and a report.
4. Do NOT copy expressive prose from scraped sources into targets. Targets are Opus-written, grounded in the provided context.
5. Do NOT let Opus invent recalls, TSBs, or platform facts. Every vehicle-specific fact in a target must appear in the context block of that pair (step 5). Pairs that fail this check are dropped, not fixed.
6. Do NOT modify diagnostics.py, prompts, or the backend.

## Steps

### Step 0: State check
1. `git tag | grep eval-v1-frozen`. Missing → STOP.
2. Locate raw data: `find . -path ./.git -prune -o \( -iname "*corpus*" -o -iname "*raw*" -o -iname "*reddit*" -o -iname "*scrape*" \) -print`. Also `ls ml/ data/ 2>/dev/null`.
3. Locate any existing distillation or dataset_builder scripts. Reuse, do not rewrite.
4. Confirm `OPENROUTER_API_KEY` is set. Missing → STOP.
5. Report record counts per source and per format.

### Step 1: Normalize
scripts/distill_normalize.py: every raw record → `{"record_id", "source", "vehicle": {year, make, model, engine|null}, "dtcs": [...], "symptoms": str, "resolution": str|null, "url"}`. Drop records with no DTC and no symptoms. Log counts in/out per source.

### Step 2: Exclude eval overlap
1. Collect every `source_url` and every (year, make, model, primary DTC) tuple from eval_set.json and codeless_set.json.
2. Drop any normalized record matching on URL, or matching on the (year, make, model, DTC) tuple. Log the count dropped.
3. Write data/train/exclusions.json with the dropped record_ids and the reason.

### Step 3: Stratified sample
1. Map each record to a label in eval/taxonomy.json by DTC family and resolution text. Records that map to nothing go in an "unmapped" bucket.
2. Target 4,000 records: at most 400 per label, at most 15% from any single source, at most 10% unmapped. Prefer records with a resolution over records without.
3. Log the composition table.

### Step 4: Build context blocks
For each sampled record, assemble the same context the backend would assemble at inference: DTC definition from dtc_definitions.py (call the module, do not reimplement), NHTSA recalls/complaints for the vehicle via knowledge.py's existing client (cache by vehicle, rate-limit politely), and any known_issues.json entry. Store as `context` on the record. If retrieval returns nothing, context contains only the DTC definition; that is a valid case.

### Step 5: Synthesize targets
1. Read the backend's actual output schema (the structured response the app expects). The target must match it exactly.
2. Opus prompt (write it to data/train/synthesis_prompt.txt and do not vary it per record): given vehicle, DTCs, live data if any, and the context block, produce the structured diagnosis. Instruction: use only facts in the context for vehicle-specific claims; reason from the DTC and live data for everything else; abstain with reason when data is insufficient.
3. Model: `anthropic/claude-opus-4.5` or newer via OpenRouter. Temperature 0.3. Concurrency 8. Retry twice on transport error.
4. Save raw Opus output per record to data/train/raw_targets/<record_id>.json.
5. Log cost: tokens in/out and dollars, running total, in the report.

### Step 6: Filter
scripts/distill_filter.py, all deterministic:
1. Schema-valid against the backend output schema. Fail → drop.
2. Grounding check: extract every recall number, TSB number, and "known issue" sentence from the target; each must string-match (case-insensitive) something in the record's context block. Any miss → drop, log the invented fact.
3. Length: drop targets under 40 words or over 500.
4. Duplicate targets (exact or >0.9 Jaccard on tokens) → keep one.
5. Log drop counts by reason.

### Step 7: Format for Unsloth
data/train/cleardrive_sft.jsonl, one line per pair, chat format:
```
{"messages": [{"role": "system", "content": <the backend's actual system prompt>}, {"role": "user", "content": <vehicle + DTCs + live data + context block, in the backend's actual prompt layout>}, {"role": "assistant", "content": <target JSON as string>}]}
```
Take the system prompt and user layout from the backend code. Do not write a new one. Split 95/5 into train.jsonl and val.jsonl, stratified by label. Compute SHA256 of both; write data/train/MANIFEST.json.

### Step 8: Report
notes/<date>-brief-2c-report.md, sections: (1) raw counts per source, (2) exclusion count, (3) sample composition, (4) synthesis cost, (5) filter drops by reason with 5 examples of invented facts caught, (6) final pair count train/val, (7) hashes, (8) anything blocked.

## Acceptance criteria
1. Tag eval-v1-frozen existed before any synthesis call.
2. Final train.jsonl between 3,000 and 5,000 pairs; val.jsonl 5%.
3. Zero pairs match any eval case on URL or (year, make, model, DTC).
4. Every pair passes schema and grounding checks.
5. System prompt and user layout in the pairs are byte-identical to what the backend sends at inference.
6. MANIFEST.json and report exist.
